# torch-tbccl 0.2.1 validation (draft)

```{warning}
**This is not a certification.** torch-tbccl 0.2.1 is a patch release of 0.2.0 that adds the benchmark provider. The runtime evidence of the previous release stands because no runtime code changed; this page records what is specific to 0.2.1. The release has not been published yet, so the release-artifact checks below are listed as not done.
```

## What changed

The benchmark provider (`benchmarks/provider`, provider protocol 1) and its documentation. The backend, the `ProcessGroup` behaviour, PyTorch 2.13.x, CPython 3.13, TBCCL C ABI 1 and wire protocol 4 are unchanged.

## Provider tests

The provider tests (21, two skipped without PyTorch) pass in a PyTorch-free interpreter and in the PyTorch environment: `describe` and `validate` output against the protocol schema, rejection of invalid workload configurations, hashing of the workload scripts and of the compiled extension, and the standalone entry point.

## Two-host smoke (development tree)

With torch-tbccl 0.2.0 wheels on both hosts (Linux CUDA, macOS Apple silicon, direct Thunderbolt 4 link) the shared runner executed a bounded set of workloads through the provider: CPU point-to-point, an all-reduce, CUDA to MPS point-to-point and a small DDP step. All 10 points passed their correctness checks with clean link health and confirmed cleanup on both hosts. These are smoke checks of the launch path, not performance measurements.

## Not yet done for 0.2.1

- The physical benchmark smoke from the released artifacts (editable and development installs are not release qualification).
- The current-release entry in the ecosystem manifest, which is changed only after the GitHub release exists.
