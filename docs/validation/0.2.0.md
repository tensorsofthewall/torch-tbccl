## Configuration under test

| | |
|---|---|
| PyTorch / CPython | 2.13.0 / 3.13 |
| TBCCL | C ABI 1, wire protocol 4 (development tree) |
| Linux | x86-64, NVIDIA RTX 3070 Ti Laptop GPU, CUDA 13 |
| macOS | Apple silicon, MPS |
| Physical link | direct Thunderbolt 4 cable between the two hosts |

## Test suites (recorded results, historical)

| Suite | Result |
|---|---|
| Linux (CPU, CUDA, DDP, lifecycle, failure, mixed traffic, capability matrix; MPS tests skip) | 229 passed, 59 skipped |
| macOS (everything, including MPS and clean-install tests; CUDA tests skip) | 201 passed, 87 skipped |

## Supported-surface contract

The capability matrix (every operation x dtype x payload shape x world size and device mode, driven through the public `torch.distributed` API on loopback) is compared with the documented surface by `tests/test_capability_matrix.py`; the MPS matrix (280 records at world sizes 1 and 2) had no wrong, failed or hung cell and no deviation from the documented surface.

## Packaging

Linux CPU and CUDA wheels and the macOS wheel were built, inspected (no embedded machine paths; the macOS wheel links only system Metal, Foundation and Objective-C runtime libraries and no libtbccl) and installed into clean virtual environments where a real collective ran.

## Mixed traffic and DDP

Collectives and point-to-point on one group at world sizes 2 to 4 on CPU, CUDA and MPS in same, opposite and mirrored order; DDP with a concurrent application P2P thread (CPU world sizes 2 and 3, CUDA plus CPU, MPS plus CPU with a CPU side channel).

## Failure and lifecycle

Peer exit, abort, destroy with pending work and interpreter shutdown with an un-waited asynchronous operation (repeated runs) are bounded and report `torch-tbccl:` errors; peer-failure tests are loopback only.

## Physical Thunderbolt 4 runs

CPU, CUDA to MPS point-to-point and collectives, and DDP (10 steps, repeated cycles) with a concurrent P2P thread, in both orientations, with the PCIe AER counters read before and after: no data mismatch and zero AER errors throughout; devices preserved. No failure was injected on the physical link.

## Known limits

Listed in [Supported operations](../reference/supported-operations.md) and the [MPS guide](../guides/mps.md): `SUM` only; two-rank gather; float16 and bfloat16 reduction at world size 2 only; no reduce, scatter, reduce_scatter, all_to_all or all_gather_into_tensor; no FSDP; DDP not at world size 1; MPS limited to one submitting thread; no fault recovery.

## Not yet done for a release

A release-candidate run of the suites and packaging checks on both platforms, from release artifacts, and a repeat of the physical-link validation if the release process requires it.
